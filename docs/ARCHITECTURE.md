# Architecture and boundaries

`shared.h` defines ABI version 3 and initialization arguments with an explicit general-adapter flag. Shared controls include size, enable, theme, confinement, heartbeat and diagnostics. `install_paths.h` validates bounded AMD64/PE32+ headers for explicitly selected applications, plus the Stellaris layout and Windows Known Folder/Steam discovery. `game_profile.h` resolves Stellaris `-userdir`; general targets do not read Stellaris logs/settings. `language.h` follows the game language for Stellaris and Windows user UI language for general targets. Restart targets when updating builds.

`controller.cpp` rechecks the selected x64 process's full path and loads only its own DLL. Standalone builds prepare the DLL and 108 themes through `embedded_runtime.h`: content-derived cache directories, byte comparison against EXE RCDATA, atomic writes and rejection of application-owned reparse paths. `tools/embed_runtime.py` independently regenerates artwork before embedding. No runtime download or installer is used. Development self-tests use adjacent build outputs. Remote exports are resolved by module + RVA; initialization identity and structure size are checked again in the DLL.

The hook recognizes installed cursor resources by bitmap/hotspot signatures. It loads requested sizes through Win32 `LoadImage`, preserving the installed assets and animation in original mode, instead of rewriting assets. Replacement themes load only a numbered path under the companion's own `bin/assets/themes`. In the Stellaris adapter, only recognized handles are replaced. SetCursor's previous-handle semantics are translated back for the game. A cache retains three recent size/theme combinations per original and at most 32 replacement handles overall. Cached original signatures are revalidated to detect recycled Windows cursor handles. Unknown Stellaris pointers and invalid sizes/themes pass through.

Stellaris 4.5.1's normal, selected and dragselect files are byte-identical. This bitmap adapter therefore maps them to the first matching base pointer. The other states retain distinct generated artwork. `tools/make_themes.py` generates 12 original sets using standard-library geometry and CUR/ANI serialization, without importing any game images. The packager regenerates all 108 assets and checks byte equality before allowing them into a Release archive.

The worker refreshes about every 250 ms; the controller heartbeat updates every second. When the controller exits, restoration is requested; after heartbeat expiry, the next relevant hook/refresh also passes through the original. The hook stays resident until game exit. Abnormal process failure cannot guarantee an immediate visual update before Windows/game input refreshes.

`settings_panel.h` combines painted preview/header text with native keyboard-accessible edit, trackbar, combo, checkbox and button controls. Preview clicks cycle through roles; native theme animation frames are shown for busy/movement. `hotkeys.h` registers eight shortcuts only while the connected game or panel is foreground, checks that context again before commands, reports collisions and unregisters on focus loss. Registration checks run at 200 ms intervals; this is not a global keyboard hook.

Version 0.8 originally added `glass_style.h`: documented DWM Desktop Acrylic with opaque accessibility/OS fallback, and GDI+ drawing into premultiplied-alpha DIBs. Native controls retain input/state/accessibility behavior while subclasses paint their surfaces. The numeric edit's native rendering is made opaque to avoid zero-alpha GDI text vanishing on glass. Version 0.9 adds the redirection bitmap alpha attribute and a runtime-resolved experimental native accent backdrop; see the private-policy compatibility limits in the design document. The dedicated hidden panel regression tests these callbacks without controlling another application's UI. [Design details and manual-check limits](UI_DESIGN.md).

`window_lock.h` confines only the game client rectangle while the target is foreground and the enabled companion heartbeat is valid. It runs inside the DLL worker, so controller expiry can release a clip after abnormal controller exit. It refuses to override a different existing restriction and releases only a rectangle it still owns. Clip changes by other applications are respected. It uses the [Win32 ClipCursor](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-clipcursor) contract, without changing Windows pointer size or sensitivity.

`bridge.h` tails new records from the active single-player game log, with bounded reads/line storage and whitelisted commands. It ignores old requests on connection, recognizes file rotation and does not execute script text or programs. The Workshop package communicates through those event/log records and supplies Chinese text or English fallback across ten supported locale folders.

The core Workshop package does not replace a GUI. The optional local generator adds one effect button to a settings page supplied by the user. Such a local patch overrides that specific file, so it must load after its source UI and be regenerated after updates. Only the generator and our button effect are distributable; a generated copy of a third-party GUI is not part of the public package.

A pure Workshop implementation was investigated on Windows Stellaris 4.5.1: both ordinary cursor overlays and `replace_path` probes failed to change a marked cursor while an unrelated menu-text control confirmed that the test mod was loaded. Read-only engine inspection found direct Win32 cursor-file loading. This evidence supports the current companion design; it is not proof that all future engine versions can never expose a cursor-setting API. No proprietary binary/disassembly or extracted resources are distributed here.

The experimental general adapter learns observed native handles, recognizes standard Windows roles by signatures and gives unknown roles the base theme. Original mode uses `CopyImage`, correcting invalid extreme-size hotspots through `CreateIconIndirect`; arbitrary original ANI preservation is not guaranteed. This shares the existing cache, context, confinement and recovery logic. Only the selected main module import is patched; software-drawn cursors, dynamic resolution and calls exclusively through other modules remain outside scope. Per-target profiles, overlays, arbitrary asset import and an editor are future work. See the [feature comparison](YOLOMOUSE_COMPARISON.md).
