# Architecture and boundaries

`shared.h` defines ABI version 2: size, enable, theme, confinement, heartbeat and diagnostics, plus cursor bitmap signatures. `preferences.h` validates theme IDs and local preset values. `install_paths.h` provides the Stellaris layout adapter and Windows Known Folder/Steam discovery. `game_profile.h` reads the active game's bounded command line through SDK-declared process fields to resolve `-userdir`. `language.h` handles language preference precedence and visible strings. ABI-mismatched mappings are rejected; restart the game when updating builds.

`controller.cpp` validates the selected x64 process and loads only the DLL next to the controller. Remote addresses are resolved by module + export RVA rather than assuming ASLR addresses match. Initialization arguments carry the exact executable and resource directory, with bounded UTF-16 storage and a checked structure size. `cursor_hook.cpp` validates them again and replaces the main module's SetCursor import.

The hook recognizes installed cursor resources by bitmap/hotspot signatures. It loads requested sizes through Win32 `LoadImage`, preserving the installed assets and animation in original mode, instead of rewriting assets. Replacement themes load only a numbered path under the companion's own `bin/assets/themes`. Only recognized handles are replaced. SetCursor's previous-handle semantics are translated back for the game. A cache retains three recent size/theme combinations per original and at most 32 replacement handles overall. Cached original signatures are revalidated to detect recycled Windows cursor handles. Unknown pointers and invalid sizes/themes pass through.

Stellaris 4.5.1's normal, selected and dragselect files are byte-identical. This bitmap adapter therefore maps them to the first matching base pointer. The other states retain distinct generated artwork. `tools/make_themes.py` generates 12 original sets using standard-library geometry and CUR/ANI serialization, without importing any game images. The packager regenerates all 108 assets and checks byte equality before allowing them into a Release archive.

The worker refreshes about every 250 ms; the controller heartbeat updates every second. When the controller exits, restoration is requested; after heartbeat expiry, the next relevant hook/refresh also passes through the original. The hook stays resident until game exit. Abnormal process failure cannot guarantee an immediate visual update before Windows/game input refreshes.

`settings_panel.h` combines painted preview/header text with native keyboard-accessible edit, trackbar, combo, checkbox and button controls. Preview clicks cycle through roles; native theme animation frames are shown for busy/movement. `hotkeys.h` registers eight shortcuts only while the connected game or panel is foreground, checks that context again before commands, reports collisions and unregisters on focus loss. Registration checks run at 200 ms intervals; this is not a global keyboard hook.

`window_lock.h` confines only the game client rectangle while the target is foreground and the enabled companion heartbeat is valid. It runs inside the DLL worker, so controller expiry can release a clip after abnormal controller exit. It refuses to override a different existing restriction and releases only a rectangle it still owns. Clip changes by other applications are respected. It uses the [Win32 ClipCursor](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-clipcursor) contract, without changing Windows pointer size or sensitivity.

`bridge.h` tails new records from the active single-player game log, with bounded reads/line storage and whitelisted commands. It ignores old requests on connection, recognizes file rotation and does not execute script text or programs. The Workshop package communicates through those event/log records and supplies Chinese text or English fallback across ten supported locale folders.

The core Workshop package does not replace a GUI. The optional local generator adds one effect button to a settings page supplied by the user. Such a local patch overrides that specific file, so it must load after its source UI and be regenerated after updates. Only the generator and our button effect are distributable; a generated copy of a third-party GUI is not part of the public package.

A pure Workshop implementation was investigated on Windows Stellaris 4.5.1: both ordinary cursor overlays and `replace_path` probes failed to change a marked cursor while an unrelated menu-text control confirmed that the test mod was loaded. Read-only engine inspection found direct Win32 cursor-file loading. This evidence supports the current companion design; it is not proof that all future engine versions can never expose a cursor-setting API. No proprietary binary/disassembly or extracted resources are distributed here.

Other game adapters, software-rendered cursor interception, overlay effects, arbitrary asset import, a user-facing editor and universal process support are not implemented yet. See the [feature comparison](YOLOMOUSE_COMPARISON.md) for the precise shipped scope.
